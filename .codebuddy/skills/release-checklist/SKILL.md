# 发布检查清单技能#

## 技能概述#

发布前验证，确保所有门控通过。此技能提供结构化的发布检查清单生成工作流程，包括解析参数、加载项目上下文、扫描代码库、生成检查清单、保存和下一步。

> **仅显式调用**：仅当用户显式请求 `/release-checklist` 时才运行此技能。不要基于上下文匹配自动调用。

## 使用方式#

- 通过 Agent 触发：当用户说「发布检查清单」或相关需求时，Agent 应自动加载此 Skill
- 手动触发：`/skill release-checklist [platform]`

---

## Phase 1: 解析参数#

读取参数的目标平台（`pc`、`console`、`mobile` 或 `all`）。如果未指定平台，默认为 `all`。

---

## Phase 2: 加载项目上下文#

- 读取 `CLAUDE.md` 以获取项目上下文、版本信息和平台目标。
- 从 `production/milestones/` 读取当前里程碑，以了解此发布应该包含哪些功能和内容。

---

## Phase 3: 扫描代码库#

扫描突出问题：
- 计数 `TODO` 注释
- 计数 `FIXME` 注释
- 计数 `HACK` 注释
- 注意它们的位置和严重性。

如果可用，检查任何测试输出目录或 CI 日志中的测试结果。

---

## Phase 4: 生成发布检查清单#

```markdown
## 发布检查清单：[版本] — [平台]

生成：[日期]

### 代码库健康度#
- TODO 计数：[N]（[如有许多则列出前 5 个]）
- FIXME 计数：[N]（[列出所有 — 这些是潜在阻塞项]）
- HACK 计数：[N]（[列出所有 — 这些需要审查]）

### 构建验证#
- [ ] 在所有目标平台上构建成功
- [ ] 无编译器警告（零警告政策）
- [ ] 所有资源包含并正确加载
- [ ] 构建大小在预算内（[目标大小]）
- [ ] 构建版本号正确设置（[版本]）
- [ ] 构建可从标记的提交中重现

### 质量门控#
- [ ] 零个 S1（严重）错误
- [ ] 零个 S2（重要）错误 — 或有制作人批准的文档化例外
- [ ] 所有关键路径功能已测试并由 QA 签署
- [ ] 在预算内：
  - [ ] 在最低规格硬件上达到目标 FPS
  - [ ] 内存使用在预算内
  - [ ] 加载时间在预算内
  - [ ] 长时间游戏会话无内存泄漏
- [ ] 与先前构建无回归
- [ ] 浸泡测试通过（4+ 小时连续游玩）

### 内容完成#
- [ ] 所有占位符资源替换为最终版本
- [ ] 内容文件中的所有 TODO/FIXME 已解决或文档化
- [ ] 所有面向玩家的文本已校对
- [ ] 所有文本本地化就绪（无硬编码字符串）
- [ ] 音频混音定稿并批准
- [ ] 制作人员名单完整且准确
```

根据参数添加平台特定部分：

**对于 `pc`：**
```markdown
### 平台要求：PC#
- [ ] 验证并记录最低和推荐规格
- [ ] 键盘+鼠标控制完全功能
- [ ] 控制器支持已测试（Xbox、PlayStation、通用）
- [ ] 分辨率缩放已测试（1080p、1440p、4K、超宽）
- [ ] 窗口化、无边框和全屏模式工作正常
- [ ] 图形设置正确保存和加载
- [ ] Steam/Epic/GOG SDK 已集成并测试
- [ ] 成就功能
- [ ] 云存档功能
- [ ] Steam Deck 兼容性验证（如果目标）
```

**对于 `console`：**
```markdown
### 平台要求：主机#
- [ ] TRC/TCR/Lotcheck 要求检查表完成
- [ ] 平台特定控制器提示正确显示
- [ ] 暂停/恢复正常工作
- [ ] 用户切换正确处理
- [ ] 网络连接丢失正常处理
- [ ] 存储已满场景处理
- [ ] 家长控制受尊重
- [ ] 平台特定成就/奖杯集成已测试
- [ ] 第一方认证提交已准备
```

**对于 `mobile`：**
```markdown
### 平台要求：移动端#
- [ ] 应用商店指南合规性验证
- [ ] 所有必需的设备权限已证明合理并文档化
- [ ] 隐私政策已链接且准确
- [ ] 数据安全/营养标签已完成
- [ ] 触摸控制在多个屏幕尺寸上已测试
- [ ] 电池使用在可接受范围内
- [ ] 后台行为正确（暂停、恢复、终止）
- [ ] 推送通知权限正确处理
- [ ] 应用内购买流程已测试（如果适用）
- [ ] 应用大小在商店限制内
```

**商店和发布部分（所有平台）：**
```markdown
### 商店 / 发行#
- [ ] 商店页面元数据完成并校对
  - [ ] 简短描述
  - [ ] 完整描述
  - [ ] 功能列表
  - [ ] 系统要求（PC）
- [ ] 屏幕截图最新且符合平台分辨率要求
- [ ] 预告片最新并批准
- [ ] 关键美术和胶囊图像最新
- [ ] 年龄分级已获得并配置：
  - [ ] ESRB
  - [ ] PEGI
  - [ ] 其他必需的地区分级
- [ ] 法律通知、EULA 和隐私政策已就绪
- [ ] 第三方许可证归属已完成
- [ ] 所有地区的定价已配置

### 发布准备度#
- [ ] 分析 / 遥测已验证并接收数据
- [ ] 崩溃报告已配置且仪表板可访问
- [ ] 首日补丁已准备并测试（如果需要）
- [ ] 发布后前 72 小时的待命时间表已设置
- [ ] 社区发布公告已起草
- [ ] 媒体/影响者密钥已准备用于分发
- [ ] 支持团队已简要介绍已知问题和 FAQ
- [ ] 回滚计划已文档化（如果发布后发现严重问题）

### 继续 / 不继续评估#

**建议**：[继续 / 有条件继续 / 不继续]

**条件**（如果有条件）：
- [必须满足的条件 1]
- [必须满足的条件 2]

**理由**：[建议的解释]

## 行动项#
| # | 行动 | 负责人 | 截止日期 |
|---|--------|-------|----------|
[数据行]
```

---

## Phase 5: 保存检查清单#

向用户展示检查清单以及：总检查清单项数、已知阻塞项（FIXME/漏洞计数）、平台特定要求数。

询问："我可以将此写入 `production/releases/release-checklist-[version].md` 吗？"

如果可以，写入文件，必要时创建目录。

---

## Phase 6: 下一步#

结论：**完成** — 发布检查清单已生成并保存。

- 在发布之前运行 `/gate-check` 以获取正式的阶段门控判定。
- 通过 `/team-release` 协调签署。
