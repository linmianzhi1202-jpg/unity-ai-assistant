# 迭代状态技能

## 技能概述

显示当前冲刺进度，突出显示阻塞。这是一个快速的态势感知检查，不是冲刺审查。它读取当前冲刺计划和故事文件，扫描状态标记，并在 30 行内生成简洁的快照。有关详细的冲刺管理，请使用 `/sprint-plan update` 或 `/milestone-review`。

**此技能是只读的。** 它从不提议更改，从不需要写入文件，并且最多做一个具体建议。

## 使用方式

- 通过 Agent 触发：当用户说「迭代状态」或相关需求时，Agent 应自动加载此 Skill
- 手动触发：```/skill sprint-status [参数]```

**参数**: `$ARGUMENTS[0]` (空白 = 使用当前冲刺)

---

## 1. 查找冲刺

**参数**: `$ARGUMENTS[0]` (空白 = 使用当前冲刺):

- 如果给定参数（例如 `/sprint-status 3`），在 `production/sprints/` 中搜索匹配 `sprint-03.md`、`sprint-3.md` 或类似文件的文件。报告找到了哪个文件。
- 如果未给定参数，在 `production/sprints/` 中找到最近修改的文件并将其视为当前冲刺。
- 如果 `production/sprints/` 不存在或为空，报告："未找到冲刺文件。使用 `/sprint-plan new` 开始冲刺。"然后停止。

完整读取冲刺文件。提取：
- 冲刺编号和目标
- 开始日期和结束日期
- 所有故事或任务条目及其优先级（必须有 / 应该有 / 最好有）、负责人和预估

---

## 2. 计算剩余天数

使用今天日期和冲刺文件中的冲刺结束日期，计算：
- 冲刺总天数（结束减去开始）
- 已过天数
- 剩余天数
- 时间消耗百分比

如果冲刺文件不包含明确的日期，注意"未找到冲刺日期——跳过燃尽评估。"

---

## 3. 扫描故事状态

**首先：检查 `production/sprint-status.yaml`。**

如果存在，直接读取它——它是权威的事实来源。从 `status` 字段提取每个故事的状态。无需 Markdown 扫描。使用其 `sprint`、`goal`、`start`、`end` 字段而不是重新解析冲刺计划。

**如果 `sprint-status.yaml` 不存在**（旧冲刺或首次设置），回退到 Markdown 扫描：

1. 如果条目引用故事文件路径，检查文件是否存在。读取文件并扫描状态标记：DONE、COMPLETE、IN PROGRESS、BLOCKED、NOT STARTED（不区分大小写）。
2. 如果条目没有文件路径（冲刺计划中的内联任务），在该条目旁边扫描冲刺计划本身的状态标记。
3. 如果未找到状态标记，分类为 NOT STARTED。
4. 如果引用了文件但不存在，分类为 MISSING 并注意它。

使用回退时，在输出底部添加注释：
"⚠ 未找到 `sprint-status.yaml`——状态从 Markdown 推断。运行 `/sprint-plan update` 生成一个。"

可选地（仅快速检查——不要进行深度扫描）：在 `src/` 中 grep 与故事的系统别名匹配的目录或文件名以检查实施证据。这只是一个提示，不是确定的状态。

### 过期故事检测

在为所有故事收集状态后，检查每个 IN PROGRESS 故事是否过期：

- 对于每个有引用文件的故事，读取文件并查找前置元数据或标头中的 `Last Updated:` 字段（例如 `Last Updated: 2026-04-01` 或 `updated: 2026-04-01`）。接受任何合理的日期字段名称：`Last Updated`、`Updated`、`last-updated`、`updated_at`。
- 使用今天日期计算自该日期以来的天数。
- 如果日期超过 2 天前，将故事标记为**过期**。
- 如果在故事文件中未找到日期字段，注意"无时间戳——无法检查是否过期。"
- 如果故事没有引用文件（内联任务），注意"内联任务——无法检查是否过期。"

过期故事包含在输出表中并收集到"需要注意"部分（参见阶段 5 输出格式）。

**过期故事升级**：如果任何 IN PROGRESS 故事被标记为过期，燃尽判定至少升级为**有风险**——即使完成百分比在正常按计划窗口内。记录此升级原因："有风险——[N] 个故事在 [N] 天内没有进展。"

---

## 4. 燃尽评估

计算：
- 完成任务（DONE 或 COMPLETE）
- 进行中任务（IN PROGRESS）
- 已阻塞任务（BLOCKED）
- 未开始任务（NOT STARTED 或 MISSING）
- 完成百分比：（完成 / 总数）* 100

通过比较完成百分比与时间消耗百分比来评估燃尽：

- **按计划**: 完成 % 在时间消耗 % 的 10 个百分点内或领先
- **有风险**: 完成 % 落后时间消耗 % 10-25 个百分点
- **落后**: 完成 % 落后时间消耗 % 超过 25 个百分点

如果日期不可用，跳过燃尽评估并报告"按计划 / 有风险 / 落后：未知——未找到冲刺日期。"

---

## 5. 输出

保持总输出在 30 行或更少。使用此格式：

```markdown
## 冲刺 [N] 状态 — [今天日期]
**冲刺目标**: [来自冲刺计划]
**剩余天数**: [N] / [总数] （[消耗时间 %]）

### 进度: [完成/总数] 任务 ([%])

| 故事 / 任务         | 优先级     | 状态        | 负责人   | 阻塞项        |
|----------------------|------------|-------------|---------|----------------|
| [标题]              | 必须有  | 完成        | [负责人] |                |
| [标题]              | 必须有  | 进行中 | [负责人] |                |
| [标题]              | 必须有  | 已阻塞     | [负责人] | [简要原因] |
| [标题]              | 应该有    | 未开始 | [负责人] |                |

### 需要注意
| 故事 / 任务         | 状态      | 最后更新   | 过期天数 | 备注           |
|----------------------|-------------|----------------|------------|----------------|
| [标题]              | 进行中 | [日期或 N/A]  | [N 天]   | [过期 / 无时间戳——无法检查是否过期 / 内联任务——无法检查是否过期] |

*（如果没有进行中的故事过期或有时间戳问题，完全省略此部分。）*

### 燃尽: [按计划 / 有风险 / 落后]
[1-2 句话。如果落后：哪些必须有任务有风险。如果按计划：确认并注意团队可以拉取的任何应该有任务。]

### 有风险的必须有任务
[列出任何已阻塞或未开始且剩余冲刺时间少于 40% 的必须有故事。如果没有，写"无。"]

### 新出现的风险
[从故事扫描中可见的任何风险：缺失文件、级联阻塞器、没有负责人的故事。如果没有，写"未识别。"]

### 建议
[一个具体行动，或"冲刺按计划进行——无需行动。"]
```

## 6. 快速升级规则

在输出之前应用这些规则，如果触发则在输出顶部（在状态表上方）放置标志：

**关键标志**——如果必须有故事已阻塞或未开始且剩余冲刺时间少于 40%：

```
冲刺有风险：[N] 个必须有故事未完成且剩余 [X]% 冲刺时间。建议使用 `/sprint-plan update` 重新计划。
```

**完成标志**——如果所有必须有故事都已完成：

```
所有必须有任务已完成。团队可以从应该有积压中拉取任务。
```

**缺失故事标志**——如果任何引用的故事文件不存在：

```
注意：[N] 个冲刺计划中引用的故事文件缺失。运行 `/story-readiness sprint` 验证故事文件覆盖。
```

## 协作协议

此技能是只读的。它报告磁盘上文件观察到的事实。

- 它不更新冲刺计划
- 它不更改故事状态
- 它不提议范围削减（那是 `/sprint-plan update`）
- 它每次运行最多做一个建议

有关特定故事的更多详细信息，用户可以直接读取故事文件或运行 `/story-readiness [path]`。

有关冲刺重新计划，请使用 `/sprint-plan update`。

有关冲刺结束回顾，请使用 `/milestone-review`。
