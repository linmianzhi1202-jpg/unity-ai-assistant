# 启动检查清单技能

## 技能概述

正式启动验证，平台提交，营销材料。此技能提供结构化的游戏发布前检查清单，涵盖代码、内容、质量、商店、基础设施、社区和运营七个主要领域。

**重要**：此技能仅当用户显式请求 `/launch-checklist` 时才运行，不要基于上下文匹配自动调用。

## 使用方式

- 通过 Agent 触发：当用户说「启动检查清单」或相关需求时，Agent 应自动加载此 Skill
- 手动触发：`/skill launch-checklist [参数]`

---

## Phase 1：解析参数

读取启动日期或 `dry-run` 模式的参数。Dry-run 模式生成检查清单而不创建签署条目或写入文件。

---

## Phase 2：收集项目上下文

- 读取 `CLAUDE.md` 以获取技术栈、目标平台和团队结构
- 读取 `production/milestones/` 中的最新里程碑
- 读取 `production/releases/` 中的任何现有发布检查清单
- 读取 `design/live-ops/content-calendar.md` 中的内容日历（如果存在）

---

## Phase 3：扫描代码库健康度

- 统计 `TODO`、`FIXME`、`HACK` 注释及其位置
- 检查生产代码中是否遗留任何 `console.log`、`print()` 或调试输出
- 检查占位符资源（搜索 `placeholder`、`temp_`、`WIP_`）
- 检查硬编码的测试/开发值（localhost、测试凭据、调试标志）

---

## Phase 4：生成启动检查清单

```markdown
# 启动检查清单：[游戏标题]
目标启动：[日期或 DRY RUN]
生成日期：[日期]

---

## 1. 代码准备度

### 构建健康
- [ ] 所有目标平台的干净构建
- [ ] 零编译器警告
- [ ] 所有单元测试通过
- [ ] 所有集成测试通过
- [ ] 性能基准在目标范围内
- [ ] 无内存泄漏（通过扩展浸泡测试验证）
- [ ] 构建大小在平台限制内
- [ ] 构建版本正确设置并在源代码控制中标记

### 代码质量
- [ ] TODO 计数：[N]（启动时要求为零，或有文档记录的例外）
- [ ] FIXME 计数：[N]（要求为零）
- [ ] HACK 计数：[N]（每个必须有文档记录的理由）
- [ ] 生产代码中无调试输出
- [ ] 无硬编码的开发/测试值
- [ ] 所有功能标志设置为生产值
- [ ] 错误处理覆盖所有关键路径
- [ ] 崩溃报告已集成并验证

### 安全性
- [ ] 源代码中无暴露的 API 密钥或凭据
- [ ] 存档数据已加密
- [ ] 网络通信已安全（TLS/DTLS）
- [ ] 反作弊措施已激活（如果有多人游戏）
- [ ] 所有服务器端点上的输入验证（如果有多人游戏）
- [ ] 隐私政策合规性已验证

---

## 2. 内容准备度

### 资源
- [ ] 所有占位符美术已替换为最终资源
- [ ] 所有占位符音频已替换为最终音频
- [ ] 音频混音已定稿并由音频总监批准
- [ ] 所有 VFX 已打磨并经过性能验证
- [ ] 无缺失或损坏的资源引用
- [ ] 资源命名约定已强制执行

### 文本和本地化
- [ ] 所有面向玩家的文本已校对
- [ ] 无硬编码字符串（全部外部化以进行本地化）
- [ ] 所有支持的语言已翻译并验证
- [ ] 文本在所有语言中适合 UI（文本适配通过）
- [ ] 所有支持语言的字体覆盖已验证
- [ ]  credits 完整、准确且最新

### 游戏内容
- [ ] 所有关卡/地图可从开始到结束游玩
- [ ] 教程流程已完成并由新玩家测试
- [ ] 所有成就/奖杯已实施并测试
- [ ] 保存/加载对所有游戏状态正常工作
- [ ] 难度设置已平衡并测试
- [ ] 终局/制作人员名单序列已完成

---

## 3. 质量保证

### 测试
- [ ] 完整回归测试套件已通过
- [ ] 零个 S1（严重）错误打开
- [ ] 零个 S2（重要）错误打开（或有文档记录的例外）
- [ ] 浸泡测试已通过（8+ 小时连续游玩）
- [ ] 多人游戏压力测试已通过（如果适用）
- [ ] 每个平台上的所有关键用户路径已测试
- [ ] 边缘情况已测试（满存储、无网络、挂起/恢复）

### 平台认证
- [ ] PC：满足 Steam/Epic/GOG SDK 要求
- [ ] 主机：TRC/TCR/Lotcheck 提交已准备
- [ ] 移动：遵守 App Store/Play Store 指南
- [ ] 可访问性：满足最低标准（按键重映射、文本缩放、色盲）
- [ ] 年龄评级已获得（ESRB、PEGI、地区性）

### 性能
- [ ] 在最低规格硬件上达到目标 FPS
- [ ] 所有平台上的加载时间在预算内
- [ ] 所有平台上的内存使用在预算内
- [ ] 网络带宽在目标范围内（如果有多人游戏）
- [ ] 关键游戏时刻无帧卡顿

---

## 4. 商店和分发

### 商店页面
- [ ] 商店页面文案已定稿并校对
- [ ] 截图是最新的且符合平台分辨率
- [ ] 预告片是最新的并已批准
- [ ] 关键美术和胶囊图像已定稿
- [ ] 系统要求准确（PC）
- [ ] 所有地区的价格已配置
- [ ] 预购/愿望单活动已激活（如果适用）

### 法律
- [ ] EULA 已定稿并由法律部门批准
- [ ] 隐私政策已发布并链接
- [ ] 第三方许可证归属已完成
- [ ] 音乐/音频许可已验证
- [ ] 商标/IP 许可已确认
- [ ] GDPR/CCPA 合规性已验证（数据收集、同意、删除）

---

## 5. 基础设施

### 服务器（如果有多人游戏/在线）
- [ ] 生产服务器已配置并加载测试
- [ ] 自动扩展已配置并测试
- [ ] 数据库备份已配置
- [ ] CDN 已配置用于内容交付
- [ ] DDoS 保护已激活
- [ ] 监控和警报已配置

### 分析和监控
- [ ] 分析管道已验证并接收数据
- [ ] 崩溃报告已激活且仪表板可访问
- [ ] 服务器监控仪表板已上线
- [ ] 关键指标已跟踪：DAU、会话长度、留存率、崩溃
- [ ] 已为关键阈值配置警报

---

## 6. 社区和营销

### 社区准备度
- [ ] 社区指南已发布
- [ ] 审核团队已简报并准备好工具
- [ ] Discord/论坛/社交渠道已设置
- [ ] FAQ 和已知问题页面已准备
- [ ] 支持电子邮件/工单系统已激活

### 营销
- [ ] 发布预告片已发布
- [ ] 媒体/影响者评测密钥已分发
- [ ] 社交媒体发布日帖子已安排
- [ ] 发布日博客文章/开发者更新已起草
- [ ] 发布版本的补丁说明已发布

---

## 7. 运营

### 团队准备度
- [ ] 发布后前 72 小时的待命时间表已设置
- [ ] 事件响应剧本已由团队审查
- [ ] 回滚计划已文档记录并测试
- [ ] 热修复管道已测试（可在 4 小时内发布紧急修复）
- [ ] 发布问题的沟通计划（谁发布、在哪里、多快）

### 发布日计划
- [ ] 发布日补丁已准备（如果需要）
- [ ] 服务器解锁/上线程序已文档记录
- [ ] 发布监控仪表板已被所有负责人添加书签
- [ ] 发布日作战室/频道已建立

---

## 启动/不启动决策

**整体状态**：[准备就绪 / 未准备就绪 / 有条件]

### 阻塞项
[列出启动前必须解决的任何项]

### 有条件项
[列出有文档记录的解决方法或已接受风险的项]

### 所需签署
- [ ] 创意总监 — 内容和体验质量
- [ ] 技术总监 — 技术健康和稳定性
- [ ] QA 负责人 — 质量和测试覆盖
- [ ] 制作人 — 时间表和整体准备度
- [ ] 发布经理 — 构建和部署准备度
```

## Phase 5：保存检查清单

向用户展示完成的检查清单和摘要（总项数、阻塞项数、有条件项数、部分不完整的部门）。

如果不在 dry-run 模式，询问："我可以将其写入 `production/releases/launch-checklist-[date].md` 吗？"

如果可以，写入文件，必要时创建目录。
