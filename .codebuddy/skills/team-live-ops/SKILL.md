# 团队直播运营技能

## 技能概述

协调多代理团队规划直播运营活动，包括赛季结构、经济平衡、数据分析、社区管理和叙事主题。

## 使用方式

- **通过 Agent 触发**：当用户说「团队直播运营」或相关需求时，Agent 应自动加载此 Skill
- **手动触发**：`/skill team-live-ops [赛季名称或活动描述]`
- **使用示例**：`/skill team-live-ops season 3 battle pass`

**参数检查**：如果未提供赛季名称或活动描述，输出：
> 用法：`/team-live-ops [赛季名称或活动描述]` — 提供要规划的赛季或活动的名称或描述。

然后立即停止，不生成任何子代理或读取任何文件。

**有参数时的行为**：当提供有效参数时，通过结构化规划流程编排直播运营团队。

**决策点**：在每个阶段转换时，使用 `AskUserQuestion` 向用户呈现子代理的方案作为可选选项。在对话中写入代理的完整分析，然后使用简洁的标签捕获决策。用户必须在继续下一阶段之前批准。

## 团队组成

- **直播运营设计师（live-ops-designer）** — 赛季结构、活动节奏、留存机制、Battle Pass
- **经济设计师（economy-designer）** — 直播经济平衡、商店轮换、货币定价、保底计时器
- **数据分析师（analytics-engineer）** — 成功指标、A/B 测试设计、活动跟踪、仪表板规格
- **社区经理（community-manager）** — 面向玩家的公告、活动描述、赛季消息
- **叙事总监（narrative-director）** — 赛季叙事主题、故事弧线、世界活动框架
- **作家（writer）** — 活动描述、奖励物品名称、赛季风味文本、公告文案

## 委托方式

使用 Task 工具生成每个团队成员作为子代理：

- `subagent_type: live-ops-designer` — 赛季/活动结构和留存机制
- `subagent_type: economy-designer` — 直播经济平衡和奖励定价
- `subagent_type: analytics-engineer` — 成功指标、A/B 测试、活动仪表化
- `subagent_type: community-manager` — 面向玩家的沟通和消息传递
- `subagent_type: narrative-director` — 赛季主题和叙事框架
- `subagent_type: writer` — 所有面向玩家的文本：活动描述、物品名称、文案

**重要**：在每个代理的提示中始终提供完整上下文（游戏概念路径、现有赛季文档、伦理政策路径、当前经济状况）。在流程允许的情况下并行启动独立代理（阶段 3 和阶段 4 可以同时运行）。

## 工作流程

### 阶段 1：赛季/活动范围界定

委托给 **直播运营设计师**：

- 定义赛季或活动：类型（赛季性、限时活动、挑战）、持续时间、主题方向
- 概述内容列表：新内容（模式、物品、挑战、故事节拍）
- 定义留存钩子：什么让玩家在这个赛季期间每天/每周回来
- 识别资源预算：需要多少新内容创建 vs. 重用
- **输出**：包含范围、内容列表和留存机制概述的赛季简报

### 阶段 2：叙事主题

委托给 **叙事总监**：

- 读取阶段 1 的赛季简报
- 设计赛季叙事主题：此活动如何与游戏世界连接？
- 定义玩家在活动期间将发现的中心故事钩子
- 识别此赛季可以推进的现有传说线索
- **输出**：叙事框架文档（主题、故事钩子、传说连接）

### 阶段 3：经济设计（如果主题明确，与阶段 2 并行）

委托给 **经济设计师**：

- 读取赛季简报和 `design/live-ops/economy-rules.md` 中的现有经济规则
- 设计奖励轨道：免费层进度、高级层价值主张
- 规划赛季内经济：赛季货币、商店轮换、定价
- 定义任何随机元素的保底计时器机制和运气保护
- 验证高级轨道中没有付费获胜物品
- **输出**：包含奖励表、定价和货币流的经济设计文档

### 阶段 4：数据分析和成功指标（与阶段 3 并行）

委托给 **数据分析师**：

- 读取赛季简报
- 定义成功指标：参与率目标、留存提升目标、Battle Pass 完成率
- 设计赛季期间运行的任何 A/B 测试（例如，不同的奖励节奏）
- 指定此赛季内容所需的新遥测事件
- **输出**：包含成功标准和仪表化需求的数据分析计划

### 阶段 5：内容编写（并行）

**并行委托**：

- **叙事总监**（如果需要）：为此赛季编写任何游戏内叙事文本（过场动画脚本、NPC 对话、世界活动描述）
- **作家**：编写所有面向玩家的文本 — 活动名称、奖励物品描述、挑战目标文本、赛季风味文本
- 两者都应读取阶段 2 的叙事框架文档

### 阶段 6：玩家沟通计划

委托给 **社区经理**：

- 读取赛季简报、经济设计和叙事框架
- 起草赛季发布公告（语调、关键亮点、平台特定版本）
- 规划沟通节奏：发布前预告、发布日帖子、赛季中期提醒、最后一周 FOMO 推送
- 为第 1 天补丁说明起草已知问题部分占位符
- **输出**：包含每个接触点草稿文案的沟通日历

### 阶段 7：审查 and 签署

收集所有阶段的输出并呈现 consolidated 赛季计划：

- 赛季简报（阶段 1）
- 叙事框架（阶段 2）
- 经济设计和奖励表（阶段 3）
- 数据分析计划和成功指标（阶段 4）
- 已编写内容清单（阶段 5）
- 沟通日历（阶段 6）

向用户呈现总结：

- **内容范围**：正在创建什么
- **经济健康检查**：奖励轨道感觉公平且不掠夺吗？
- **数据分析准备情况**：是否定义并仪表化了成功标准？
- **伦理审查**：对照 `design/live-ops/ethics-policy.md` 检查阶段 3 经济设计
  - 如果文件不存在：标记"ETHICS REVIEW SKIPPED: `design/live-ops/ethics-policy.md` not found. Economy design was not reviewed against an ethics policy. Recommend creating one before production begins." 在赛季设计输出文档中包含此标志。添加到下一步：创建 `design/live-ops/ethics-policy.md`。
  - 如果文件存在且发现违规：标记"ETHICS FLAG: [element] in Phase 3 economy design violates [policy rule]. Approval is blocked until this is resolved." 不要发出 COMPLETE 判定或写入输出文档。使用 `AskUserQuestion` 提供选项：修订经济设计 / 用文档化基本原理覆盖 / 取消。如果用户选择修订：重新生成经济设计师以生成更正的设计，然后返回阶段 7 审查。
- **开放问题**：生产开始前仍需决策的事项

在委托给制作团队之前，要求用户批准赛季计划。只有在用户批准后且没有明确违规的情况下才发出 COMPLETE 判定。如果伦理违规未解决，以判定 **BLOCKED** 结束。

## 输出文档

所有文档保存到 `design/live-ops/`：

- `seasons/S[N]_[name].md` — 赛季设计文档（来自阶段 1-3）
- `seasons/S[N]_[name]_analytics.md` — 数据分析计划（来自阶段 4）
- `seasons/S[N]_[name]_comms.md` — 沟通日历（来自阶段 6）

## 错误恢复协议

如果任何生成的代理（通过 Task）返回 BLOCKED、错误或无法完成：

1. **立即上报**：在继续依赖阶段之前，向用户报告 `[AgentName]: BLOCKED — [reason]`
2. **评估依赖关系**：检查被阻止代理的输出是否被后续阶段需要。如果是，在没有用户输入的情况下不要超过该依赖点。
3. **通过问题确认提供选项**，选择包括：
   - 跳过此代理并在最终报告中注明差距
   - 以更窄的范围重试
   - 停在此处并首先解决阻止程序
4. **始终生成部分报告** — 输出任何已完成的工作。永远不要因为一个代理被阻止而丢弃工作。

如果 BLOCKED 状态无法解决，以判定 **BLOCKED** 结束，而不是 COMPLETE。

## 文件写入协议

所有文件写入（赛季设计文档、数据分析计划、沟通日历）都委托给通过 Task 生成的子代理。每个子代理强制执行"我可以写入 [path] 吗？"协议。此编排器不直接写入文件。

## 输出

包含以下内容的总结：赛季主题和范围、经济设计亮点、成功指标、内容列表、沟通计划，以及生产前需要用户输入的任何开放决策。

**判定**：**COMPLETE** — 赛季计划已生成并移交给生产。
