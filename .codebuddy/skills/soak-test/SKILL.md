# 浸泡测试技能

## 技能概述

浸泡测试（也称为耐力测试）是带有特定观察目标的扩展游戏会话。与冒烟检查（主干关键路径，约 10 分钟）或单次功能试玩（约 30 分钟）不同，浸泡测试运行 **30 分钟到数小时**，以暴露：

- **内存泄漏** — 仅在场景转换后出现的渐进堆增长
- **性能漂移** — 随时间恶化帧时间退化
- **状态累积错误** — 仅在机制重复 N 次后出现的错误（物品栏满、分数溢出、AI 状态损坏）
- **趣味疲劳** — 在第一次会话中感觉良好但在扩展游戏后变得重复的机制
- **内容耗尽** — 玩家用完新颖内容的临界点

**此技能生成观察协议和分析框架——实际游戏由人类完成。**

**输出:** `production/qa/soak-test-[date]-[duration].md`

**运行时机：**
- 抛光阶段 — 在 `/gate-check release` 之前
- 修复内存或稳定性问题后（回归浸泡）
- 当扩展游戏尚未正式跟踪时

## 使用方式

- 通过 Agent 触发：当用户说「浸泡测试」或相关需求时，Agent 应自动加载此 Skill
- 手动触发：```/skill soak-test [参数]```

---

## 1. 解析参数

**持续时间**（默认：`1h`）：
- `30m` — 短浸泡；适用于测试单个机制或场景
- `1h` — 标准浸泡；覆盖大多数常见泄漏类别
- `2h` — 扩展浸泡；推荐用于首次完整抛光浸泡
- `4h` — 深度浸泡；需要用于具有长会话设计的游戏（RPG、模拟器）

**焦点**（默认：`all`）：
- `memory` — 聚焦堆大小、对象计数、泄漏模式
- `stability` — 聚焦崩溃/冻结/挂起检测
- `balance` — 聚焦趣味疲劳、内容耗尽、难度感知
- `all` — 上述所有内容

## 3. 定义观察检查点

根据持续时间，生成定时检查点：

**30 分钟浸泡**：T+0、T+10、T+20、T+30
**1 小时浸泡**：T+0、T+15、T+30、T+45、T+60
**2 小时浸泡**：T+0、T+20、T+40、T+60、T+80、T+100、T+120
**4 小时浸泡**：T+0、T+30、T+60、T+90、T+120、T+180、T+240

在每个检查点，观察者记录阶段 4 中定义的观察项目。

## 4. 生成浸泡测试协议

### 内存/稳定性观察项目（如果焦点 = memory 或 all）

引擎特定监控指导：

**Godot 4:**
- 打开调试器 → 监视器标签；跨检查点跟踪 `内存 → 静态内存` 和 `对象计数 → 对象`
- 记录：静态内存 (KB)、对象计数、孤立节点计数
- 警报阈值：在第一个 15 分钟后，内存增长 > 20%（加载时一些增长是预期的；持续增长表示泄漏）
- 注意：`Performance.get_monitor(Performance.MEMORY_STATIC)` 在 Godot 4.6 中返回字节

**Unity:**
- 打开内存分析器（Window → Analysis → Memory Profiler）
- 记录：总预留内存 (MB)、GC 已分配 (MB)、每个检查点的对象计数
- 警报阈值：GC 已分配在 3+ 检查点中单调增长

**Unreal Engine:**
- 在每个检查点使用 `stat memory` 控制台命令
- 记录：已用物理内存 (MB)、可用物理内存
- 警报阈值：整个浸泡过程中已用物理内存增长 > 50MB

### 稳定性观察项目（如果焦点 = stability 或 all）

在每个检查点，注意：
- [ ] 自上次检查点以来没有发生崩溃、挂起或冻结
- [ ] 帧率仍在目标预算内（[目标 FPS] fps）
- [ ] 音频仍正确播放（无不同步或静音）
- [ ] 所有 HUD 元素仍正确渲染
- [ ] 输入按预期响应（无输入丢失或延迟峰值）

### 平衡/疲劳观察项目（如果焦点 = balance 或 all）

在每个检查点收集主观观察：
- [ ] 核心机制仍感觉有回报（是/否）
- [ ] 感知难度级别：[太容易 / 合适 / 太难]
- [ ] 自上次检查点以来有任何"我以前见过这个"时刻？（新颖内容耗尽）
- [ ] 自上次检查点以来有任何挫折时刻？注意原因。
- [ ] 自上次检查点以来有任何高峰参与时刻？注意原因。

## 协作协议

- **此技能生成协议——人类运行它**——永远不要尝试自动运行浸泡测试。观察需要人类观察者。
- **持续时间应匹配游戏的会话设计**——5 分钟的游戏不需要 4 小时浸泡；城市建造器可能需要。使用判断，如果不清楚就询问。
- **首次浸泡应该是 `all` 焦点**——窄焦点（仅内存）用于特定修复后的回归浸泡，不是第一次通过
- **写入前询问**——创建协议文件前始终确认
